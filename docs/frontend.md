# Go Frontend

The UI uses [go-app v11](https://pkg.go.dev/github.com/maxence-charriere/go-app/v11/pkg/app)
compiled to WebAssembly. It calls `/listens` through the generated Go OpenAPI
client and displays the response, with loading, empty, error, and retry states.
The backend currently returns `500 NOT_IMPLEMENTED`; the UI displays that error.

## Build And Run

From the repository root:

```sh
mise install
mise exec -- make run-dev
# Open http://localhost:8080
```

One backend process serves both API and static frontend files. Rebuild/restart
after changing Go UI code; there is no Vite server or automatic hot reload.

To build only the static frontend:

```sh
mise exec -- make frontend-build
```

Exported files are written to `bin/web/`, including `index.html`, go-app's
JavaScript/CSS loader, service worker, manifest, `web/app.wasm`, stylesheet,
local icon, and public config. This directory can be served by a plain static
file server. The API must also be reachable on the same origin.

`cmd/frontend` is the browser program compiled to WASM.
`cmd/frontend-export` is a build-time command that compiles it and exports assets.
UI code and source assets live in `internal/ui/`; export tooling lives in
`internal/frontendbuild/`. Generated files live under `bin/web/`, not a separate
top-level frontend project.
Neither is imported by the backend: runtime uses only
`http.FileServer(http.FS(static))`, not a go-app handler.

## Configuration

Each application owns separate configuration:

- Backend: `cmd/mnemosyne/config/local.yaml` and `docker.yaml` (`bindAddress`,
  `frontendDir`, `apiPrefix`), selected with `-config` (default `local`).
- Frontend exporter: `cmd/frontend-export/config/config.yaml` (`outputDir`,
  `resourceDir`, `apiPrefix`).
- Browser: exported `web/config.json`, containing only the frontend API prefix.

The exporter does not read backend configuration. Configure matching API prefixes
explicitly, including both leading and trailing slashes (for example `/api/`).
Invalid prefixes fail validation; code never adds missing slashes.
Settings do not come from environment variables. `GOOS`/`GOARCH` only select the
compiler target.

Frontend config is static, not fetched from the backend's configuration system.
Rebuild exported files after changes. Asset hashes provide service-worker
versioning; API responses are not included in its offline cache.

## API Generation

The client and models in `gen/client/api.gen.go` are generated by oapi-codegen
from the OpenAPI contract. Frontend never imports backend services, database
code, configuration, or `gen/api`.

```sh
mise exec -- make gen
```

Generated Go code is checked in. Do not edit it manually. Regenerate and review
`git diff -- gen/client` after contract changes. Node/npm remain in `mise.toml` only for the existing
OpenAPI lint/bundle tools; frontend compilation and Docker builds use Go only.

## Go Tooling

Frontend and backend share one Go module, `.golangci.yaml`, formatter, and tests:

```sh
mise exec -- make fmt
mise exec -- make fmt-check
mise exec -- make lint
mise exec -- make test
```

Linting additionally checks frontend for `GOOS=js GOARCH=wasm`. Tests exercise
HTTP requests against mock servers, cancellation, response rendering, strict
configuration, and exported files served without a go-app handler.

VS Code's existing Go extension and custom formatter apply to frontend `.go`
files too. No ESLint, TypeScript SDK, or npm frontend installation is required.

## Docker

```sh
make docker-start
# Open http://localhost:8080
make docker-stop
```

The Dockerfile compiles WASM, exports static files, and builds the backend in a
Go builder stage. Runtime contains the backend binary and exported files, with
SQLite persisted in `mnemosyne-data`. Stopping/removing the container preserves
that volume. Stop the existing container before rebuilding.

```sh
make docker-start DOCKER_PORT=8081 DOCKER_CONTAINER=mnemosyne-dev
make docker-stop DOCKER_CONTAINER=mnemosyne-dev
```
